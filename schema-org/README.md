# schema.org — vendored parent closure

`ontology.ttl` is **not** a copy of schema.org. It's a minimal, generated
`rdfs:subClassOf` closure for just the schema.org classes an in-house
ontology (currently `datatourisme`, in this same repository) references but
doesn't itself define — e.g. `datatourisme/ontology.ttl` declares
`<http://schema.org/LocalBusiness> a owl:Class .` with no label and no
further superclass, since it only needs `LocalBusiness` as a subclassing
*target*. Without this file that's a dead end: the class diagram/tree in the
consuming UI has nowhere further to walk, and shows a bare CURIE instead of
a real name.

Generated by
[`eona-vocabulary-services`'s `pipelines/tools/resolve-external-parents.py`](https://github.com/Eona-X/eona-vocabulary-services/blob/main/pipelines/tools/resolve-external-parents.py)
(that script lives in the consuming repo, not here): seeds from every such
stub class, walks `rdfs:subClassOf` in a full copy of schema.org (fetched,
not committed) up to each root (`schema:Thing`), and writes out just the
label + subClassOf triples for that closure.

Not independently published (no `metadata.toml` here) — it deliberately
carries no `owl:Ontology` triple of its own, so it isn't picked up by the
publish pipeline's completeness check as an in-house hub ontology requiring
its own catalog card. `generate.py` merges the relevant slice of it into
whichever ontology's own generated output actually references those classes
(currently `datatourisme`, but any other hub ontology gaining a
`schema.org` reference would pick up its own matching slice too —
`merge_relevant_closure` only copies the classes transitively reachable
from what THAT ontology references, not the whole file, so an ontology
referencing one schema.org class doesn't also pull in everything a
different ontology needed from here).

Regenerate after adding a new `rdfs:subClassOf <http://schema.org/...>`
reference somewhere in the hub that isn't covered here yet, from an
`eona-vocabulary-services` checkout with this repo as its
`pipelines/vocabularies` submodule:

```sh
python3 pipelines/tools/resolve-external-parents.py \
    --namespace http://schema.org/ \
    --source https://schema.org/version/latest/schemaorg-current-http.ttl \
    --seed-from pipelines/vocabularies/datatourisme/ontology.ttl \
    --out pipelines/vocabularies/schema-org/ontology.ttl
```

(`--seed-from` may be repeated if another ontology also references schema.org.)
